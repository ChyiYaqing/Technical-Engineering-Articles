# AI 术语详解

## **Rules vs Machine Learning（规则 vs 机器学习）**

传统软件靠规则运行。开发者写下「如果这样，就那样」，程序就严格照办。它永远不会自己变好。

机器学习把这件事翻了过来。你不再去写规则，而是给系统喂样例（数据），让它自己学出其中的模式。它见到的相关数据越多，预测或生成输出的能力就越强，不需要人把每种情况都硬编码进去。

## **Transformers（Transformer 架构）**

Transformer 是当今几乎所有主流 AI 模型（GPT、Claude、Gemini 等等）背后的架构。在 Transformer 出现之前，模型按顺序逐词处理文本，很难理解跨度较长的上下文。

Transformer 引入了一种叫「attention（注意力）」的机制，让模型能一次性看到句子（或文档）里的所有词，并判断哪些词彼此之间最重要。正是这一点，让模型能理解诸如「它」指代五句话之前提到过的某样东西这类上下文。

## **LLMs（Large Language Models，大语言模型）**

LLM 是一种基于 Transformer 的模型，在海量文本上训练，用来预测序列中的下一个词（严格说是下一个「token」）。把这件事做到足够好、规模足够大，模型就会开始写作、推理、总结、回答问题，表现出一种看起来颇具智能的样子。

GPT、Claude 和 Llama 都是 LLM。「大」指的是参数数量（模型在训练中调整的内部数值），通常是数十亿量级。

## **Temperature and Context Window（温度与上下文窗口）**

你会反复遇到的两个设置项：

**Temperature（温度）** 控制输出的随机程度。温度低（接近 0）时，模型更可预测、更聚焦。温度高时，模型更有创造性、更多变，但也更容易跑偏。

**Context window（上下文窗口）** 指模型一次能「看到」多少文本，以 token 计量。如果一个模型有 128k token 的上下文窗口，那大致就是它在开始遗忘最早那部分内容之前，所能纳入考虑的文本量（你的对话、文档、代码等等）。

## **Chatbots vs AI Agents（聊天机器人 vs AI 智能体）**

聊天机器人负责回答问题。你问，它答，对话结束。它不记得自己在现实世界里做过什么，除了生成文本之外也没有实际做事的能力。

AI agent（AI 智能体）则更进一步。它能采取行动：调用 API、运行代码、搜索网页、更新数据库，然后根据这些行动的结果决定下一步做什么。核心区别在于：聊天机器人说话，智能体做事。

## **Agent Loop（智能体循环）**

Agent loop 是 AI 智能体为完成任务而不断重复的循环：

Observe（观察当前状态或输入）

Think（决定下一步做什么）

Act（调用工具或执行动作）

Observe the result（观察结果）

重复，直到任务完成

正是这个循环，把单次 LLM 调用变成了能处理多步骤、真实世界任务的东西。

## **ReAct Pattern（ReAct 模式）**

ReAct 是「Reasoning and Acting（推理与行动）」的缩写。这是一种提示词模式：要求模型用文本明确地把问题推理一遍（Thought，思考），决定要执行的动作（Action，行动），看到结果（Observation，观察），然后重复。

这让模型的决策过程变得可见，而不是一个黑盒；同时它通常能提升多步骤任务的准确率，因为模型被迫在行动之前「把思路说出来」。

## **Tools（工具）**

Tools 是 AI 模型可以调用的函数或 API，用来做它自己做不到的事，比如搜索网页、运行代码、查询数据库、发送邮件。模型本身并不执行工具；它只决定用哪个工具、传什么输入，真正运行并返回结果的是外围系统。

正是这套机制，把 LLM 从「只会生成文本」变成了能与真实系统交互的东西。

## **AI Memory (and Amnesia)（AI 记忆与失忆）**

默认情况下，LLM 在不同对话之间没有记忆。每一次新对话都从零开始，这常被称为「AI amnesia（AI 失忆）」。除非把相关信息显式地再喂进提示词，模型不会记得你的名字、你的偏好，也不会记得昨天发生的任何事。

AI memory（AI 记忆）指的是搭在模型之上、用来解决这个问题的系统：把关于用户或任务的事实存起来，之后再检索出相关部分注入到后续对话中，让模型表现得像是「记住了」。

## **RAG（Retrieval-Augmented Generation，检索增强生成）**

LLM 只知道它训练时见过的东西，而训练数据有一个截止日期。RAG 通过在查询时把新鲜、相关的信息拉进来，解决了这个问题。

它的工作方式是这样的：你的文档或数据被切成若干块（chunk）存起来（通常存在向量数据库里）。当一个问题进来时，系统检索出最相关的那些块，喂进模型的上下文，于是模型就能基于当下的、具体的信息作答，而不是纯粹依赖训练时记住的内容。

## **MCP（Model Context Protocol，模型上下文协议）**

MCP 是一套标准化的方式，让 AI 模型连接外部工具和数据源，比如 Salesforce、GitHub 或文件系统，而不必为每一个都专门做一套定制集成。

可以把它想成一个通用适配器。你不用每想让模型对接一个新服务就写一遍定制代码，MCP 定义了一套共同的协议，任何符合规范的工具都能接入任何符合规范的模型。

## **Smart Agent Architectures（智能体架构设计）**

这指的是单个智能体内部如何组织结构，才能做出好的决策，而不是盲目地条件反射。它通常包含：

- 规划层（把大任务拆成小步骤）
- 记忆（短期和长期）
- 工具访问能力
- 推理循环（比如 ReAct）来决定下一步做什么

一个「聪明的」智能体架构，其设计目标是让智能体能应对模糊不清的情况、从错误中恢复、在任务中途调整计划，而不是照着一份僵硬的脚本往下走。

## **Multi-Agent Architectures（多智能体架构）**

与其让一个智能体包揽所有事情，多智能体架构把工作拆分给若干个各有专长、彼此协作的智能体。比如一个负责规划，一个负责写代码，一个负责评审，还有一个负责与用户沟通。

这和人类团队的工作方式很像：专业分工提升质量，再由一个协调者（有时称为「orchestrator agent（编排智能体）」）来管理它们之间的交接。

另外几个值得了解的概念

**Embeddings（嵌入向量）**：文本（或图像）的数值表示，能够捕捉含义，让相似的概念在数学空间中彼此靠近。这是让 RAG 和语义搜索成为可能的基础。

**Vector database（向量数据库）**：一种专门用来存储嵌入向量、并按相似度而非精确关键词匹配进行检索的数据库。

**Fine-tuning（微调）**：拿一个预训练模型，在一个更小、更特定的数据集上继续训练，让它在某个具体任务或领域上表现更好。

**Hallucination（幻觉）**：模型信誓旦旦地生成了虚假或编造的信息。之所以会这样，是因为模型是在预测看起来合理的文本，而不是在查证事实——除非用 RAG 之类的手段显式地为它提供依据。

**Prompt engineering（提示词工程）**：精心设计输入（提示词）的做法，目的是从模型那里拿到更好、更可靠的输出。

**Guardrails（护栏）**：围绕模型输入输出设置的规则或过滤器，用来保证它安全、不跑题、不越界。
